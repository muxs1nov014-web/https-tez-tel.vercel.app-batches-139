# Assumptions

- [2026-09-30] Which batch's cost applies when selling a model held in several batches? → FIFO: oldest batch first (the admin can override the batch on a sale) → standard for wholesale; keeps profit per batch traceable.
- [2026-09-30] Is `(esim)` a separate product? → Yes, a product variant attribute (eSIM-only) → it has a different purchase price in the data.
- [2026-09-30] Bot language? → Replies in Uzbek (Latin); understands Uzbek Latin/Cyrillic and Russian → the client writes Latin, and the Excel uses Cyrillic.
- [2026-09-30] Non-phone goods (Dyson, tablets)? → The catalog is generic "product", not phone-only → the data contains them.
- [2026-09-30] Rate per row? → The AED→USD rate is stored on every purchase line (default 3.67) → data has 3.657–3.685.
- [2026-09-30] Meaning of the `(1)` suffix? → An import **channel** on the purchase line ("hand"), with `customs_factor` 0.5 applied to the rastamojka estimate; the default channel "cargo" has factor 1.0. Both are editable in the admin panel → matches the data (107.5 = 215 × 0.5) and keeps it out of the product identity.
- [2026-09-30] Sign of `(-) Bojxona boji`? → Added to cost, as in Excel → keeps historic unit costs identical to the client's numbers.
- [2026-09-30] Client import service in v1? → Yes, minimal: optional `client_id` + `service_pct` on a purchase line, excluded from own stock, plus one report → the client said "Ha, 1-versiyada" and the cost engine already covers it.
- [2026-09-30] Do `B/U xar`, `Upakovka`, `1 Sim tam`, `Inspector` count in unit cost? → Yes, all four, as per-unit costs → a cost is a cost; Excel's exclusion looks like a range bug, and those columns are almost never filled (≤12 rows).
- [2026-09-30] How is an **actual** batch total for a per-line category (e.g. rastamojka) spread over lines? → Proportional to each line's estimate (qty × estimate per unit); equal per unit if the estimate total is 0. Batch-level categories are always equal per unit (D3) → rastamojka differs by model 10×, so an equal split would be wrong.
- [2026-09-30] Excel legacy import: batch totals repeated on each line of a date? → Batch total = Σ(line value × line qty) / day qty, which reproduces Excel's per-unit share exactly when the values are equal → matches `SUMIF` semantics.
- [2026-09-30] Batch status tracking (Dubai → in transit → customs → on sale)? → Not in v1; every own purchase line counts as stock → came only from the "(2)" file.
- [2026-09-30] Bot transport? → Long polling (no public webhook needed) → simpler on a VPS; can switch to a webhook later.
- [2026-09-30] Gemini model? → Configurable via `GEMINI_MODEL`, with a Flash-class default → speed requirement.
- [2026-09-30] Who may delete? → Admin: batches, sales, tariffs, users. Operator may delete a batch **line** or **expense** row, because expenses have no edit and this is how typos get fixed. Both are blocked once sales exist → keeps data entry fast without letting an operator erase sales history.
- [2026-09-30] Opening balance re-run after sales? → Units sold after `as_of` are subtracted from the counted qty; a re-run replaces all previous opening-balance write-offs of the product → found in review; prevents phantom stock.
- [2026-10-01] Host ports collide with other local projects (80/443/8080/5433)? → Ports are env-driven: WEB_HTTP_PORT/WEB_HTTPS_PORT (default 80/443), DB_PORT (default 23432); local .env uses 23080/23443/23432 → the 23xxx range is unused by any other container on this machine.
- [2026-10-01] Which Gemini model on a free-tier key? → gemini-3.5-flash-lite (15 req/min) instead of gemini-3.8-flash (5 req/min, frequent 503 overload) → user asked for the higher-limit option; one bot question costs 2–3 requests.
- [2026-10-01] Excel rows 424 (date 30.02.2026, 6 units) and 848 (no AED price, 1 unit) were skipped by the importer → left out and must be entered manually in the panel once the client gives the real date and price → re-import skips dates already present, so it cannot add them.
- [2026-10-02] What is a customer's "qoldiq"? → Consignment: goods handed over from our stock on credit stay ours until the customer sells them; each customer is a separate warehouse (user's choice) → SPEC §12.
- [2026-10-02] How is debt formed? → opening debt + all sales to the customer + client-service charges − payments (user's choice). Handover does not create debt; a reported sale does. `exposure` also shows debt + value of the goods still at the customer → covers both readings of "nasiya".
- [2026-10-02] Return order? → LIFO from the customer's latest handover; consignment sale allocation FIFO → mirrors physical flow, keeps cost consistent.
- [2026-10-02] Who sees customer buttons in the bot? → Every allowed bot user (same whitelist as AI questions) → bot users are staff added by admin.
- [2026-10-02] Sign of `qty` / `total_qty` in a `return` move response (§12.4 does not say)? → The admin panel shows absolute values and takes the direction from `kind` → works whether the backend sends positive or signed quantities.
- [2026-10-02] Ledger `debit` / `credit` when not applicable, and what `ref_id` points to? → Numbers (0, shown as "—"), not null; `ref_id` of a `sale` row is the sale id (linked to `/sales/:id`), and other types are not linked → §12.4 marks only `ref_id` as nullable.
- [2026-10-02] Negative debt? → Shown as the customer's advance (green). The payment form warns when a payment exceeds the debt but does not block it → debt is a plain sum, so overpayment is possible.
- [2026-10-02] Handover price and payment amount precision? → Rounded to 2 decimals on submit (`NUMERIC(12,2)` / `NUMERIC(14,2)`). The consignment sale price is sent as typed (sale_lines keep 4 decimals) → avoids 422 errors on columns with 2 decimals.
- [2026-10-02] Backend: what does overview `sold_qty` count? → Units sold from the customer's warehouse (consignment sales), so `given_qty − returned_qty − sold_qty = stock_qty`; `charged_sales` still covers both sources → keeps the warehouse identity checkable. Quantities in move responses are positive; the direction comes from `kind`.
- [2026-10-02] Backend: consignment sale allocation order? → Oldest batch first among the customer's lines (the same FIFO key as stock sales) → cost stays consistent with our own sales.
- [2026-10-02] Backend: deleting a `return` move? → Also refused (422) if our warehouse would go negative (the returned units were already sold or handed on). §12.2 named only the customer-side check → without this, stock could go negative.
- [2026-10-02] Backend: deleting a purchase line or batch after a handover? → Refused (409) while any consignment entry references the line, even a fully returned one → required by the FK, keeps the audit trail, and mirrors the existing "has sales" rule.
- [2026-10-02] Backend: extra indexes `consignment_entries(move_id)` and `(sale_line_id)` beyond §12.1? → Added → they serve the ON DELETE CASCADE lookups (every sale delete probes this table), following the project's habit of indexing FK parent columns.
- [2026-10-02] Backend: how strict is the LIFO on returns? → It works per purchase line: lines are ranked by their latest handover to that customer (newest first, then newer batch), and each line gives back up to the customer's qty on it. This is not a strict per-handover-document LIFO → quantities are always right; only the cost basis of the returned units can differ when one line was handed over several times. Not worth the extra complexity for 7–8 customers.
- [2026-10-02] How do users sign in to the Telegram Mini App? → Telegram initData verified on the backend and mapped to users.telegram_id set by an admin; login form as fallback → no passwords typed in Telegram, and no new roles (SPEC §13).
- [2026-10-02] Set the bot menu button to the Mini App now? → No; behind WEBAPP_URL, left empty → the bot token is currently shared with the BonviHR project and the quick-tunnel URL changes on restart.
- [2026-10-02] Backend: how does `/start` show both the "👥 Mijozlar" reply keyboard and the inline "📱 Panelni ochish" button (SPEC §13.3)? → Two messages: the welcome with the reply keyboard, then a short "Boshqaruv paneli…" message with the inline WebApp button → one Telegram message carries one keyboard kind, and a reply-keyboard WebApp button would not give the Mini App the signed initData it needs to log in.
- [2026-10-02] Backend: `WEBAPP_URL` set but not https? → Treated as empty (no button, no menu-button call) and a warning is logged at bot startup; a failed `setChatMenuButton` call is logged, not fatal → Telegram rejects non-https Mini App URLs, and the bot's AI and customer menus should keep working without the menu button.
- [2026-10-02] Backend: limits on `telegram_id` and `init_data`? → `telegram_id` must be > 0 and < 2^63 (else 422); `init_data` is capped at 8192 characters (else 422), and an empty string is a 401 "imzosi topilmadi" → Telegram user IDs are positive and the column is BIGINT; real initData is under 2 KB.
- [2026-10-02] Backend: is a repeated key or a future `auth_date` in initData accepted? → A repeated key is refused (401); a future `auth_date` is accepted → a repeated key makes "which value was signed" ambiguous, while `auth_date` is inside the signed data, so only Telegram can set it.
- [2026-10-02] Panel button placement? → Reply keyboard "📱 Panel" next to "👥 Mijozlar" (client's choice); no menu button, no inline message. Telegram sends no initData there, so it is a one-time login form instead of auto-login → client asked for a single regular button.
